# POD 图片去重与归档管理系统：简明使用手册

## 1. 首次使用前

1. 确认 MySQL 5.7.40 服务正在运行：

   ```powershell
   Get-Service MySQL57
   ```

   状态应为 `Running`。如未运行，请在管理员 PowerShell 执行：

   ```powershell
   Start-Service MySQL57
   ```

2. 根目录必须有 `.env`。请以 `.env.example` 为模板，填写本机数据库连接；不要提交 `.env`、密钥或真实图片路径。

3. 在 PowerShell 中进入项目根目录并安装依赖：

   ```powershell
   cd D:\pod-dedup
   powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\bootstrap.ps1
   ```

## 2. 启动系统

分别打开三个 PowerShell 窗口，并在每个窗口执行以下一条命令：

```powershell
cd D:\pod-dedup
.\scripts\start_api.ps1
```

```powershell
cd D:\pod-dedup
.\scripts\start_worker.ps1
```

```powershell
cd D:\pod-dedup
.\scripts\start_frontend.ps1
```

打开浏览器访问：`http://127.0.0.1:5173`

如需确认后端状态，访问：`http://127.0.0.1:8000/api/v1/health`

关闭 API、Worker 或前端窗口即可停止对应服务；不会停止 MySQL。

也可使用一键启动：

```powershell
cd D:\pod-dedup
.\scripts\start_all.ps1
```

它会在未运行时尝试启动 `MySQL57`、API、Worker 和前端；如果后端虚拟环境或前端依赖目录缺失，会先安装依赖。需要强制按锁文件重新同步后端依赖时，使用 `./scripts/start_all.ps1 -SyncDependencies`。已有服务需要重新加载代码时，使用 `./scripts/start_all.ps1 -Restart`；该参数只会停止本项目监听 8000、5173 端口的进程和项目 Worker，再重新启动它们。

## 3. 页面与字段说明

- 页面使用「顶部一级导航 + 左侧二级菜单」：**工作台**用于建任务；**任务与审核**用于看进度、审核与审计；**系统**用于健康检查、日志和设置。
- 目录输入框既可直接手动输入/粘贴绝对路径，也可点击 **浏览**。按钮会在运行 API 的同一台 Windows 桌面电脑上打开原生选择器，可逐层进入目录后确认。
- **来源图片流程**只需要两个目录：本次来源文件夹、历史源图库。
- **POD 图片流程（MJ 直入）**只需要两个目录：POD 待处理目录、历史 POD 图库；不需要来源文件夹。
- 历史源图库、历史 POD 图库标题后的 **锁定** 按钮可固定常用目录。锁定后输入框和“浏览”都会禁用；点击“已锁定 · 解锁”后才能修改。锁定状态只保存在当前浏览器本机。
- **输出比例**是 POD 任务的生产比例，例如 `3x4`、`9x16`。
- **仅检测模式**只生成结果和操作计划，不移动、复制或删除任何文件。首次使用建议先开启。

所有路径必须是当前电脑可访问的绝对路径。不要把来源批次目录设为历史源图库，也不要把 POD 待处理目录放在 POD 图库内部。

## 4. 日常操作流程

### A. 开始来源去重

1. 在「来源图片流程」填写本次来源文件夹、历史源图库。
2. 建议首次勾选“仅检测模式”，点击 **开始来源去重**。
3. 检查任务中心的扫描数、删除计划、告警和逐图明细。
4. 确认无误后关闭仅检测模式，再次执行。

系统会自动删除字节或像素完全相同的本次来源图。无法可靠判断的视觉候选会保留，不会因为单个相似度分数自动删除。

### B. 整理已处理来源图

外部 AI 抠图工具成功处理来源图后，应将成功文件放进：

```text
本次来源文件夹\已处理\
```

点击 **整理已处理来源图** 后，系统会：

- 将未重复图片移动到历史源图库根目录；
- 按实际整理时间重命名为 `YYYYMMDDHHmmSSsss.ext`；同毫秒不同内容时使用 `_1`、`_2` 避让；
- 删除已确认的精确重复；
- 保留未处理、失败或不支持的文件。

### C. 开始 POD 去重

1. 在「POD 图片流程（MJ 直入）」填写 POD 待处理目录、历史 POD 图库。
2. 点击 **开始 POD 去重**。
3. 系统直接处理 POD 待处理目录；MJ 直入任务会明确记录“已跳过来源整理”。
4. 精确重复会自动删除本次新文件；视觉候选会进入人工审核。
5. 全部审核结束后，系统会自动统一归档，无需额外点击“确认归档”。

归档后的 POD 原图会按实际归档时间重命名为 `YYYYMMDDHHmmSSsss.ext`，位于 POD 图库根目录；不按比例过滤或裁切。

```text
Production\比例\执行日期\
```

需要生产素材时，进入「POD 裁切与生产素材」：按原图文件名的 `YYYYMMDD` 日期范围选择原图，选择或新增比例（如 `2:3`），系统居中裁切并将独立结果写入上述 `Production` 目录。起止日期均包含在筛选范围内。裁切图命名为 `原图名_比例.ext`，例如 `20261008112203854_1x1.png`；原图不变，裁切图不做二次去重。

## 5. 人工审核与永久删除

人工审核页会按“候选关联组”同时显示本批图片、历史匹配图和机器证据：两张图片左右并列，三张及以上使用网格展示。镜像候选（例如 A 对 B 与 B 对 A）只显示为同一个候选组；这只是便于比较，不代表系统已确认组内全部重复。

在候选组内，默认每张图片都勾选“保留此图”。如果确认组内为重复，可取消勾选需要删除的图片，勾选永久删除确认后点击“重复，删除未保留图片”。至少必须保留一张；系统会对每个实际删除文件重新核验身份并保留操作证据。也可选择“重复，全部保留”“不是重复，全部保留”，或“暂不确定”让整个候选组继续等待审核。

- **重复，删新图**：删除本批图片。
- **重复，删旧图**：删除历史主文件及所有已登记分类副本。
- **重复，均保留**：保留两张，但记录为重复关系。
- **不是重复**：保留两张，并复用该结论避免同一内容版本反复审核。
- **暂不确定**：不删除，继续保留。

点击任意删除决定前，必须勾选“我确认永久删除”。删除不可恢复高清原图；系统会在删除前保存缩略图证据、判断记录和文件操作记录。

## 6. 任务进度、日志与诊断

- 创建任务后，页面会自动跳转到 **任务与审核 → 当前任务进度**，每 2.5 秒自动刷新，无需手工刷新页面。
- 如果参数填错或重复创建了任务，可在「全部任务」或「当前任务进度」点击 **取消**。系统会在当前单图文件操作完成后停止后续处理；已经完成的移动、删除或裁切不会回滚，且仍可在操作记录中核对。
- 「全部任务」显示任务 ID、创建时间、开始/结束时间、状态及处理/删除/归档/待审/错误计数。
- 「当前任务进度」显示冻结清单的逐图阶段、错误代码和按时间排列的任务事件。
- 「系统 → 服务健康」可确认 API、MySQL、Worker、DINOv2、三类 FAISS 索引、VLM 和目录是否可用。
- 「系统 → 运行日志与诊断」可下载 JSON 诊断文件；如果已选中任务，文件仅包含该任务的状态、错误代码、审核/操作状态及最近运行日志。诊断文件不包含真实路径、图片名或密钥，可直接发给技术支持分析。

## 7. 设置与索引

- **建立/重建三类索引**：创建后台索引任务，Worker 会重建来源整图、来源印花和 POD 三类 FAISS 索引。
- **来源高确定视觉自动删除**：默认关闭。只有先完成真实人工样本验证并勾选确认后，才允许启用；仍要求 ROI、结构化 VLM 和本地印花对应证据同时通过。
- **VLM**：未配置时系统会保守降级并保留图片。API Key 只能写入，页面不会回显。
- **时区、比例容差、VLM 预算**：保存后只影响新建任务；已经创建的任务使用创建时冻结的设置。

## 8. 常见问题

### `bootstrap.ps1` 一闪而过或报解析错误

请不要双击脚本。打开 PowerShell 后执行：

```powershell
cd D:\pod-dedup
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\bootstrap.ps1
```

### 页面无法打开

检查 API、Worker、前端三个窗口是否仍在运行；再访问健康检查地址确认 MySQL 状态。

### 任务一直显示“等待审核”

这是正常的保守行为。请在人工审核区完成或暂缓每个候选；最后一条审核结束时系统才会统一归档该批 POD。

### 人工审核提示“该审核已完成”

通常是双击，或最后一条审核触发归档后旧卡片尚未移除。页面会自动刷新审核列表；请不要再次点击同一张卡片。若反复出现，请在「运行日志与诊断」下载当前任务诊断 JSON 一并提供。

### 目录被占用

同一个 POD 待处理目录同时只能有一个未结案任务。请完成现有审核或等待任务终止后再创建新任务。

### VLM 未就绪

未配置 VLM 不会阻断精确去重、归档和人工审核；只会减少复杂视觉判断能力，系统会保留不确定图片。
